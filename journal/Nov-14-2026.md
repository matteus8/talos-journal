# The Missing Device Tree Trap: Debugging Pi 5 Dark Ethernet & True BCM2712 Talos

Following up from [Nov 13](./Nov-13-2026.md), we were ready to boot the Raspberry Pi 5 control plane. But edge bare-metal rarely behaves on the first attempt without a proper debugging story.

---

## 1. The Incident: Solid Green LED, Dead Ethernet PHY

After flashing the MicroSD card and powering up the Pi 5:
- **Power**: CanaKit 45W USB-PD power supply plugged into a wall outlet (sufficient 5A supply).
- **Peripherals**: Official active cooler fan spinning smoothly.
- **LED State**: Board power LED showed solid green.
- **Network State**: The RJ45 Ethernet jack LEDs remained **completely dark** (no link, no activity).
- **Diagnostic Link**: Connecting a direct Cat6 cable between the Mac's Gigabit adapter and the Pi 5 returned:
  ```output
  status: inactive
  ```
  Zero physical PHY link pulses were detected by the Mac. No ARP entries appeared, and `192.168.1.100` was unreachable.

The obvious thought was to drag out a micro-HDMI cable and hook the board to a monitor as a last resort to see the console output. But before rearranging the desk, we performed an autopsy on the raw disk image itself.

---

## 2. The Autopsy: The `rpi_generic` vs. `rpi_5` Architecture Trap

On macOS, we mounted the FAT32 boot partition (`EFI`) of the flashed image to see what the board was actually reading:

```bash
diskutil image attach -nomount .cache/images/pi5-factory.raw
mkdir -p /tmp/pi5-boot
diskutil mount readOnly -mountPoint /tmp/pi5-boot /dev/disk4s1
ls -la /tmp/pi5-boot/*.dtb
```

The output revealed the smoking gun:
```output
bcm2708-rpi-b-plus.dtb
bcm2708-rpi-b.dtb
bcm2709-rpi-2-b.dtb
bcm2710-rpi-3-b-plus.dtb
bcm2711-rpi-4-b.dtb
bcm2711-rpi-cm4.dtb
```

**There was not a single `bcm2712` device tree blob on the disk!**

### Why Did This Happen?
1. **The Broadcom BCM2712 Hardware Reality**:
   - Raspberry Pi 4 uses the **BCM2711** SoC and boots with `bcm2711-rpi-4-b.dtb`.
   - Raspberry Pi 5 uses the completely redesigned **BCM2712** SoC paired with the **RP1 southbridge chip** over PCIe. It strictly requires `bcm2712-rpi-5-b.dtb` (and `bcm2712d0-rpi-5-b.dtb` for D0 silicon steppings).
2. **The Overlay Mismatch**:
   - The generic Talos SBC overlay profile `rpi_generic` (and older `sbc-raspberrypi:v0.1.0`) was built for Pi 4/3/2/1.
   - Sidero Labs split Raspberry Pi 5 into its own dedicated overlay: profile `rpi_5` bundled in `ghcr.io/siderolabs/sbc-raspberrypi:v0.3.0`.
3. **The Silent Failure Mode**:
   - When the Pi 5 powers on, its onboard EEPROM bootloader searches the boot partition specifically for `bcm2712-rpi-5-b.dtb`.
   - Failing to find it, the EEPROM halts the ARM CPU immediately with a solid green LED.
   - Because the CPU halts in the EEPROM before U-Boot or Linux ever starts, the kernel never initializes the RP1 southbridge PCIe bus.
   - Because the RP1 chip is uninitialized, the Broadcom BCM54213PE Gigabit PHY never receives power or clock pulses. The RJ45 port stays completely dead with no link lights.
   - A monitor would have simply displayed: `"Device-tree file 'bcm2712-rpi-5-b.dtb' not found"`.

---

## 3. The Solution: Local DoD Depot Container Build for `rpi_5`

Rather than relying on the cloud Image Factory with generic overlays, we executed the build 100% locally on the Mac using the official Sidero `imager` container pinned to `sbc-raspberrypi:v0.3.0`:

```bash
# 1. Decrypt control plane config safely in-memory
TMP_CONFIG=$(mktemp)
SOPS_AGE_KEY_FILE=./age.key sops -d configs/controlplane.enc.yaml > "$TMP_CONFIG"

# 2. Run local Talos Imager targeting rpi_5
docker run --rm \
  -v "$TMP_CONFIG:/workspace/controlplane.yaml" \
  -v "$(pwd)/.cache/images:/out" \
  ghcr.io/siderolabs/imager:v1.14.5 rpi_5 \
  --arch arm64 \
  --overlay-image ghcr.io/siderolabs/sbc-raspberrypi:v0.3.0 \
  --overlay-name rpi_5 \
  --extra-kernel-arg "ip=192.168.1.100::192.168.1.1:255.255.255.0::end0:off:1.1.1.1" \
  --embedded-config-path /workspace/controlplane.yaml

rm -f "$TMP_CONFIG"
xz -dc .cache/images/metal-arm64.raw.xz > .cache/images/pi5-prebaked.raw
```

### Verification of the New Image:
Mounting the EFI partition of the new `.cache/images/pi5-prebaked.raw`:
```output
-rwx------  bcm2712-rpi-5-b.dtb
-rwx------  bcm2712d0-rpi-5-b.dtb
-rwx------  bcm2712-d-rpi-5-b.dtb
-rwx------  bcm2712-rpi-500.dtb
-rwx------  bcm2712-rpi-cm5-cm5io.dtb
-rwx------  config.txt
-rwx------  u-boot.bin
```
And inside the UKI initramfs:
```output
discovered system extensions: embedded-config
kernel command line: talos.platform=metal console=tty0 console=ttyAMA10,115200 ... ip=192.168.1.100::192.168.1.1:255.255.255.0::end0:off:1.1.1.1
```

All BCM2712 device tree files are present, the static IP parameters are baked into GRUB/UKI, and the machine config is embedded into the initramfs extension.
